# Objective

Use the Har-390 Codex-producer/Claude-consumer evidence to reduce confirmation,
pull-request, latency, and token overhead while preserving asynchronous safety,
writer isolation, durable recovery, and autonomous progress.

# Nightly gate and method

Remain gated until the owner starts a nightly run. Establish a reproducible
baseline from Har-390 for confirmations, protected publications, elapsed time,
and context cost per completed checkpoint. Design and benchmark the smallest
protocol changes that safely batch same-authority, same-risk, no-source work;
automate deterministic receipt reconciliation where possible; and avoid
producer queue toggles that add no safety information.

# Invariants

Never batch across an owner decision, new authority, live/private source,
external write, changed input after failure, ambiguous outcome, repository or
client boundary, or independently reviewable correction. Preserve exact
request binding, value-free reports, idempotence, no pane reads, producer-only
paths, consumer-only paths, protected publication, terminal receipts, and
restart-safe recovery. Do not use live connectors, private data, or external
mutations in benchmarks.

# Acceptance

Add focused synthetic benchmarks and regressions, report before/after evidence,
and demonstrate fewer confirmations and publications on representative
multi-stage Personal-style tasks without weakening any frozen boundary. Run
complete Harness validation and publish through protected main. Promote only
generic behavior; keep project-specific privacy and source policy local.
