# Portfolio coordination

Harness is the direct portfolio coordinator, not a Harness-local producer or
consumer. Personal, Students, Swallow, Website, and future onboarded projects
may retain repository-native producer/consumer ledgers. Before coordinating
one, enter its exact root, read its root policy and selected packet, fetch, and
use its repository-local validator. Never copy private payloads into Harness.

Producer/consumer roles in a sibling repository are coordination defaults, not
permission tiers. Preserve immutable task identity, queue parity, atomic state
updates, and protected publication. A consumer may cross a producer-owned path
when the in-scope solution requires it after checking overlap and recording the
reason. Messages are optional transport; durable repository state, not an
interactive checkpoint loop, authorizes asynchronous work.

A sibling consumer report does not create a Harness task. Reconcile its status
in that sibling repository. A Harness nightly may inspect and improve sibling
ledgers, but only Harness starts the nightly and private findings stay in their
own repositories.
