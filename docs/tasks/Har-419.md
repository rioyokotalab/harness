# Har-419 — Require Slack services to survive startup settling

Swallow enrollment reported success after one immediate `systemctl is-active`
check, but the broker failed 172 milliseconds later during synchronous profile
validation. The installer therefore accepted a transient active state instead
of a usable service.

Add a shared bounded service-settling check: require active state immediately,
wait one second for synchronous startup validation, then require active state
again. Apply it to Personal and Swallow enrollment and service refresh paths.
Swallow binding uses the same check and restores the prior profile when the
second probe fails. Focused tests prove both probes, the exact delay, and the
late-failure rollback; the complete Slack and integrated gates pass. Runtime
task execution is unaffected because the delay occurs only during privileged
installation or refresh. Har-419 is complete with the protected candidate.
