# T-372 — Complete interrupted worktree teardown

## Status

Active publication candidate after clean local phase one. Implementation is
isolated on `codex/t372-worktree-recovery`; no owner choice remains.

## Problem

T-370 records exact `directory-deleted` and `admin-deleted` checkpoints and
tests that the expected residue remains after a synthetic interruption. It
does not provide a later invocation that consumes those checkpoints and
finishes the archive audit, administration cleanup, expected-old branch
deletion, and final state transition. A normal re-plan rejects a missing
worktree path, while the original guarded manifest also expires. Durable
recording alone therefore does not satisfy idempotent recovery.

## Frozen implementation

Add one explicit recovery mode that accepts exactly one private worktree-apply
state receipt. Re-open its immutable plan without reusing an expired deletion
token; resolve the recorded candidate by exact path, branch, and tip; verify
repository identity, current merged-PR classification, archive receipt, path
absence, administration identity/backlink or absence, and expected-old local
branch. If administration remains, create and consume a fresh single-target
guarded manifest. Then delete only the exact branch ref and advance the same
state receipt through `admin-deleted`, `branch-deleted`, and `complete`.

Completed recovery is a value-free idempotent no-op. Reject an unsafe state
file, changed repository, changed branch tip, existing worktree directory,
unknown archive, wrong admin path/owner/backlink, or non-merged classification.
Do not add a daemon, scan arbitrary state automatically, mutate remote refs, or
weaken ordinary closeout gates.
