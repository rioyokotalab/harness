## Status

isolated task worktrees mandatory. Each canonical reference checkout is still

## Objective

At the first independently verified idle or cold-restart boundary for each
managed session, preserve its exact task branch in an isolated worktree and
restart that project's managed client from the isolated path. Return the
canonical reference checkout to clean, freshly fetched `main`. Keep phone,
tmux, saved-thread, and recovery mappings coherent without replaying a prompt.

## Acceptance

- Record exact primary path, task branch, tip, upstream, dirty and ignored
  state, linked worktrees, and process ownership without reading pane or
  transcript content.
- Prove the task tip remains reachable in a distinct isolated worktree before
  changing the canonical checkout.
- Change runtime cwd only through the managed recovery workflow at an idle or
  cold-restart boundary; never relocate a live process or app-server root.
- Return the canonical checkout to clean `main` at current `origin/main`, then
  validate saved-root, tmux, phone, monitor, and cold-restart recovery state.
- Run each repository's owning validator. Preserve unrelated work and do not
  change required approval counts or remote branches.

## Trigger and first action

The trigger is an owner-visible idle/cold-restart boundary for Students or
Swallow, not merely process liveness. Before acting, read that repository's
current ledger and the managed-client policy, then inventory only the selected
project's path and process metadata. If the boundary is absent or ambiguous,
leave the repository and runtime untouched.
