# T-370 — Enforce symmetric task-worktree lifecycle

## Status

Complete. PR #551 merged the implementation as
`85d59a1d99ea8f19b1489b23651dc87d2fe578f9` on 2026-08-01.

## Objective

Make structural isolation and cleanup the default for repository-native Codex
and Claude work. Every mutable task gets an isolated worktree from freshly
verified protected `main`; shared reference checkouts remain clean on `main`.
Task close archives exact tips, removes only clean and inactive worktrees, and
deletes branches through expected-old transactions.

## Frozen design

Use T-363 option A. Do not add a lease for correctness or observability until
measured evidence shows a need. Integrate creation and teardown with the
existing housekeeping surface instead of creating another monitor or daemon.
Never stash owner work, never infer merge by branch name or diff, and treat
ignored files, nested repositories, locks, processes, and open files as
independent fail-closed gates.

## Acceptance

- Both clients use the same repository-local task-worktree contract.
- A reference checkout dirty or off `main` is reported before task creation.
- Closeout proves exact merged-PR head or preserved archive, validates all
  worktree residue classes, and uses guarded deletion plus expected-old refs.
- Interrupted cleanup is idempotently reconcilable without chat history.
- Focused lifecycle tests and final `harness validate` phase one pass.
- No managed session, phone root, project repository policy, or required
  approval count changes.

## Exact next action

None for T-370. Apply the lifecycle to new mutable tasks. T-371 separately
tracks migration of the two pre-existing managed primary branches when their
live sessions reach a safe boundary.

## Verified implementation checkpoint

The housekeeping surface now accepts an explicit primary repository, task
branch, absent scratch path, and exact freshly fetched `origin/main` OID. It
rejects linked roots, dirty or off-main reference checkouts, divergent/stale
tips, existing refs/paths, symlinked parents, and paths outside declared
scratch boundaries. GitHub PR discovery executes from the selected repository,
fixing the cross-repository misclassification observed during T-369.

Worktree closeout retains every prior fail-closed residue and liveness check,
archives the exact eligible tip, guarded-removes the directory and Git admin
record, audits the archive, then expected-old deletes the local branch.
Durable phases distinguish directory, admin, and branch completion; synthetic
interruptions after directory and admin deletion prove recoverable residue.
