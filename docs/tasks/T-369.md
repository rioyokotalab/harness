## Frozen benchmark

For every repository, acceptance requires all applicable rows:

1. The active board contains only high-value work or a material explicit
   event/authority gate; completed, duplicate, superseded, and speculative
   entries are absent from the active queue but remain durably auditable.
2. Every retained or new item identifies an outcome, first executable action,
   evidence/acceptance gate, and external trigger or authority when blocked.
3. No active, dirty, locked, open, unmerged, unpublished, uniquely referenced,
   or otherwise non-reconstructable branch, worktree, or temporary artifact is
   deleted.
4. Every cleanup candidate has identity, ownership, archive/reachability, and
   process/open-file evidence; bulk cleanup uses guarded manifests and is
   audited afterward.
5. Repository-specific focused checks pass, broad policy/lifecycle changes run
   the repository's full required suite, and protected publication preserves
   concurrent work without force updates.
6. Recommendations map to authoritative primary sources or reproducible local
   evidence and are classified adopt, adapt, experiment, reject, or unresolved.
7. The final tree and ledger disclose no credentials or private Personal data,
   and the repositories remain operationally independent.

Raw numbers of deleted files, branches, worktrees, or tasks are deliberately
not success metrics.

The owner's request authorizes ordinary repository work, evidence-backed board
replacement, and cleanup that passes existing guarded gates. Repository Git
operations may use isolated task branches, fetch, commit, push, pull request,
and protected merge. It does not waive project policy or authorize external
service administration, deployments, messages, credentials, unsafe deletion,
or destruction of ambiguous work.

Before mutation, record each target's instructions, full active board,
revision, upstream, dirty ownership, worktrees, branches, stashes, locks,
