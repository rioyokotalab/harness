# Har-401 — Make Claude-to-controller messaging first-class

The owner-requested Local Codex/Claude round-trip exposed a compatibility
defect: `send-local-codex` forces both source and target clients to Codex. A
Local Claude sender therefore resolves itself as the Harness Codex source and
fails before submission; its truthful Claude prefix would also fail message
validation.

## Scope

- Let the Codex-target compatibility send and reply commands declare a Claude
  source client while preserving Codex as the default.
- Let the matching compatibility reader select the same source client.
- Document the exact Local Claude-to-Harness Codex route and keep the generic
  client-explicit route authoritative.
- Add focused regressions for truthful attribution, target selection, output,
  and backward compatibility.

## Outcome

`send-local-codex`, `reply-local-codex`, and
`read-local-codex-report` now accept an optional `--source-client` with the
historical Codex default. A Local Claude sender can therefore target Harness
Codex through the compatibility interface while retaining a truthful
`[Agent: Local Claude]` prefix and Claude-keyed report recovery state.

The local-agent and delivery references now show the exact cross-client
controller route and keep the generic client-explicit interface authoritative.
Focused tests cover one-way Local Claude-to-Harness Codex delivery, structured
Claude compatibility reports and readback, and unchanged default Codex use.

## Next action

None after protected publication and one completion report to Local Claude.
