# Har-427 — Make the complete Harness suite portable on macOS

## Outcome and scope

Make `tests/test-phase1.sh` execute truthfully on Riken macOS while preserving
its Linux contract. Replace accidental GNU/Linux and newer-Python assumptions
with native platform mappings or explicit fixture-controlled skips. Do not
weaken safety invariants, convert real failures into unconditional skips,
install packages, alter credentials, touch managed panes, or change external
services.

## Baseline and classification

- Harness started clean and synchronized at protected merge
  `fbc87dc5f02cccd57014868ef1af885b67f95221`; working branch is
  `codex/har427-portable-phase1`.
- The Riken complete suite ran 99 focused suites in 318.958 seconds and failed
  29. The task-owned Har-426 suite passed.
- Confirmed compatibility groups include Python 3.9 use of
  `zip(strict=...)`/missing `tomllib`, GNU `stat`/`touch`/`sha256sum`
  assumptions, Linux-only `SO_PEERCRED`, macOS Unix-socket path limits,
  Linux-only service tests that should use declared fixture platforms, and
  tests whose timing or current tmux/Git state leaks into isolated fixtures.
- The first durable failure is `tools/harness-ledgers.py`: the required board
  selector cannot run under Riken's system Python 3.9 because it uses
  `zip(..., strict=True)`.

## Execution order

1. Restore the mandatory ledger selector and Python 3.9 compatibility helpers.
2. Fix portable filesystem metadata, hashing, timestamp, and socket-path
   helpers shared by multiple suites.
3. Separate Linux runtime semantics from host-independent unit fixtures,
   including peer credentials and Linux-only deployment commands.
4. Repair isolated tmux, monitor, fleet, and timing fixtures without observing
   pane content or weakening production checks.
5. Rerun each changed owning suite, then the complete phase-one suite. Refresh
   only generated artifacts whose inputs changed.
6. Record remaining platform skips and exact failure evidence, then publish
   through one protected Harness PR.
