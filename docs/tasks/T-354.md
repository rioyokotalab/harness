## Frozen migration method

Wait until the existing Students runtime checkout is retired or the owner
selects a different unoccupied destination. Then:

1. Revalidate destination identity, ownership, emptiness, Git state, active
   cwd references, linked worktrees, saved roots, phone mapping, and current

2. Prepare real repository roots at both requested destinations and preserve
   every source checkout until acceptance. Do not overwrite, merge into, or
   rename over an existing destination.
3. Update the closed target map, both launch sentinels, monitor, recovery
   helper, remote-agent selector, documentation, and owning tests. Validate
   the lifecycle change with focused suites and full phase one, then publish
   it through protected `main`.
4. Migrate one project at a time using a bridge-first fresh saved root and
   provisional pane. Keep the old session available until the replacement has
   reconstructed the repository ledger, passed root/model/runtime acceptance,
   and received separate physical phone-visibility confirmation.
5. Promote only the accepted pane/root. Archive the old root only after exact
   zero-reference proof; handle any later tree removal through guarded
   deletion.

This preserves user-visible availability and durable task continuity, but it
cannot preserve the exact old saved-root or TUI process identity because the
saved cwd is immutable.
