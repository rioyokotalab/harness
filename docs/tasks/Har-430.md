1. Replace wall-clock readiness assumptions in the evaluation and
   housekeeping interruption fixtures with explicit observable handshakes.
2. Extend focused-runner contracts to retain every suite's duration and
   platform classification in a machine-readable receipt while preserving
   compact human output.
3. Stop new admission after the first failure, terminate already-running suite
   process groups gracefully, wait for their cleanup, and retain an explicit
   keep-going diagnostic mode.
4. Add a Darwin resource class so process-heavy suites have bounded concurrent
   admission while lightweight suites continue in parallel; base membership on
   measured/process-lifecycle behavior rather than host-name assumptions.
5. Add a fast Darwin preflight that covers portability and interrupt contracts,
   and prove it is documented as subordinate to the full final gate.
6. Run owning focused tests while iterating, then the repository-required full
   validation tier on the final integrated tree. Inspect cleanup and timing
   receipts independently.

Success means deterministic interrupt tests, materially earlier failure
return, complete timing evidence, bounded heavy-suite concurrency on Darwin,
a passing preflight, and an unchanged all-suite success contract. Do not claim
a successful-run speedup until matched Mac measurements exist.
