# Har-413 — Preserve stable Slack read failure classes

The one owner-authorized Personal channel read reached the broker once and
failed upstream. It returned no source content and caused no write, persistence,
or retry. The remote adapter already converts every transport and provider
failure into a bounded internal `RemoteMCPError` class, but the outer broker
collapses all those classes to `provider-failed`. That prevents value-free
diagnosis and made the consumed attempt less informative.

Preserve only internal reasons that pass the existing lowercase-hyphen runtime
filter; collapse every other exception to the existing generic class. Add
focused tests for a known provider class and a private-looking exception, run
the Slack and integrated gates, publish, and deploy before any separately
authorized changed-input read. Never replay the consumed target.
