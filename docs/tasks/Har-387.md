# Har-387 — Producer disposition semantics hardening

## Status

Phase: `active`. The producer packet is published at `816949d`; this consumer
stream owns only Harness implementation, tests, instructions, and execution
state. Sibling repository dispatch and Personal packet restoration remain
producer-owned independent streams.

## Reproduced defect

The validator deliberately permits the mutable index disposition to diverge
from an immutable packet's publication-time `state`, but selector output and
cold-start instructions did not name that distinction. A consumer therefore
treated Per-015's old `gated` packet metadata as current after the producer
index was `ready`. Separately, `check-producer-diff` allowed modification of an
already-published packet, so the mistaken repair passed validation.

## LIFO stack and next action

1. Add focused tests for a ready index with a gated publication state.
2. Reject producer modification, deletion, rename, or type change of any
   packet present in the protected base while still allowing packet addition.
3. Make selector output and cold-start instructions identify the index as the
   sole current-disposition source.
4. Run focused tests, the owning Harness validation tier, and writer-boundary
   checks before protected publication.

No credentials, hosting settings, consumer runtime state, private payload, or
sibling implementation path is in scope.
