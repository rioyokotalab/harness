# Har-410 — Make the Harness ledger integration check state-aware

The Har-403 complete gate exposed two stale integration assumptions:
`tests/test-harness-ledgers.sh` required the ordinary selector to be idle even
though the focused ledger contract explicitly permits and selects an active
ordinary task, and `tests/test-task-ledger-routing.sh` froze the prior next task
number even though adding an ordinary task must advance it.

The first integration check now accepts only the two valid bounded selector
shapes: idle, or one selected `Har-NNN` task. The routing check validates the
config schema and derives the exact next ID from the current ledger instead of
freezing an obsolete value. Synthetic owning tests continue to prove exact
selection, idle behavior, ordering, and next-ID monotonicity.
