# Har-399 — Truthful remote claude_auth probes

`harness macos-agent-session --status` run over plain SSH reports
`claude_auth=unauthenticated` on a healthy managed Mac whenever the login
keychain is inaccessible in the calling context: securityd refuses
("User interaction is not allowed"), so `claude auth status` reads no
credential and answers logged-out. Hosts holding a plaintext
`~/.claude/.credentials.json` fallback (home, office) mask the artifact; a
keychain-only host (aist) always misreports. During the 2026-08-06 aist
remote-control recovery this produced a false unauthenticated diagnosis and an
unnecessary owner re-login.

Fix: resolve Claude authentication as a three-state fact — `ok`,
`unauthenticated`, `unknown`. When the direct check answers logged-out,
distinguish a genuine logout from a locked keychain via
`security show-keychain-info`; when locked, re-check through
`tmux run-shell` in the GUI login session where the supervisor and TUI
actually run (no pane or transcript access). Only a definitive answer is
reported; an unanswerable probe reports `unknown`, never `unauthenticated`.
Run-once deferral labels carry the same state.

## Acceptance

- Direct logged-in answer short-circuits unchanged (launchd tick fast path).
- Accessible keychain plus logged-out answer stays definitive
  `unauthenticated` and still defers window creation.
- Locked keychain plus GUI-context logged-in reports `claude_auth=ok` and
  does not defer.
- Locked keychain plus GUI-context logged-out reports `unauthenticated`.
- An unanswerable GUI-context probe reports `unknown` within a bounded wait.
- No pane, transcript, or credential content is read; probe residue is
  removed by exact unlink; deterministic tests cover all states on Linux and
  macOS.

## Outcome

`harness macos-agent-session` now resolves Claude authentication once per
invocation into `ok`, `unauthenticated`, or `unknown`. A logged-out direct
answer is definitive only while `security show-keychain-info` succeeds;
behind a locked keychain the tool re-asks through `tmux run-shell` in the
GUI login session, bounded by a ten-second wait, reading only the
`loggedIn` value and removing probe files by exact unlink. Status reports
the resolved state verbatim and run-once deferral labels carry it
(`claude-deferred-unauthenticated` / `claude-deferred-unknown`). The
launchd tick path is unchanged: a logged-in host short-circuits on the
direct check.

The discriminator was verified live on aist on 2026-08-06: the same
`security show-keychain-info` call fails over plain SSH and succeeds via
`tmux run-shell`, and remote `--status` had reported `unauthenticated`
while the GUI context reported `loggedIn: true`. The owning suite covers
all four new states deterministically on Linux and macOS through `security`
and `run-shell` stubs, and the complete tier-R3 phase-one suite passed on
the final integrated tree before publication.

Deployment to managed Macs follows the standing guarded fleet-sync rollout
policy for merged control-plane changes; it is operations, not part of this
record's acceptance.
