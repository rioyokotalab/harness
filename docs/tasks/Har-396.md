# Har-396 — Equal producer and consumer permissions

## Frozen decision

The owner explicitly chose trust-equivalent producer and consumer repository
capabilities. Roles remain useful for conflict avoidance and queue ownership,
but are advisory. Consumers should normally avoid producer paths and new goals;
when a consumer believes either is necessary for an in-scope solution, it may
act without a producer relay or special owner phrase. The same Git,
publication, validation, privacy, sensitive-source, external-action, and
destructive-action rules apply to both roles.

Owner consent has no magic syntax. An unambiguous plain-language response to
the immediately preceding bounded proposal is sufficient. Restatement is
needed only for material ambiguity, changed input or scope, a separately gated
external action, or an ambiguous prior result—not to make the owner paste
agent-written words.

## Baseline and acceptance

Current role diff checks reject a consumer touching producer paths and a
producer touching implementation paths. Root instructions, producer entrypoints,
and nightly procedures state exclusive producer ownership. Acceptance requires
mixed producer/consumer diffs to pass with explicit advisories, published packet
immutability to remain enforced for both roles, no verbatim owner-authorization
requirement, full repository validation, protected publication, and clean
independent main branches.

## Outcome

All five repositories now use advisory role ownership with equal repository
capabilities, shared immutable-packet enforcement, optional checkpoint
coordination, and contextual owner approval. Personal, Students, Swallow, and
Website preserve their domain-specific hard boundaries. The repository
onboarding skill and scaffold carry the same prospective contract.
