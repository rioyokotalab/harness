  transcript content.
- Create and lock a detached isolated worktree at the exact task tip, then
  prove its object and tree identity before changing the canonical checkout.
  Do not try to check out the still-occupied branch in two worktrees.
- Treat ignored and untracked runtime state separately from Git. Preserve its
  path, ownership, type, mode, link count, and required runtime relationship
  without reading private payloads. Reconstruct declared generated state from
  repository inputs where possible; otherwise use a no-follow, byte-verified,
  current-user private transfer only when the selected project's managed
  contract requires that state in the isolated worktree.
- Change runtime cwd only through the managed recovery workflow at an idle or
  cold-restart boundary; never relocate a live process or app-server root.
- After the selected runtime is quiescent and the exact detached tip is
  durable, return the canonical checkout to clean `main` at freshly fetched
  `origin/main`; only then attach the unchanged task branch to the detached
  worktree. Abort before relaunch if either ref or worktree identity changed.
- Relaunch bridge-first from the isolated worktree, accept saved-root, tmux,
  phone, monitor, and cold-restart recovery state, and retire only the old
  quiescent leaf after the provisional path is fully accepted.
- Run each repository's owning validator. Preserve unrelated work and do not
  change required approval counts or remote branches.
- After Students is on current `main`, reconcile open Dependabot PR #560 from
  a fresh isolated task: its old-base CI failure is the expected staged
  installer digest mismatch after changing the Codex package files. Update the
  package and exact installer digest together, pass the full local gate before
  allocating another hosted run, then replace or supersede the stale PR

Swallow, not merely process liveness. Before acting, read that repository's
current ledger and the managed-client policy, then inventory only the selected
project's path and process metadata. If the boundary is absent or ambiguous,
leave the repository and runtime untouched.

value-free ignored/untracked-state classification; owner-visible quiescence;
canonical checkout fast-forward; branch attachment in the isolated worktree;
bridge-first managed recovery; independent phone/tmux/restart acceptance; old
leaf retirement. Every step revalidates the exact predecessor and records a
retry-safe checkpoint. An ambiguous stop, attach, launch, or acceptance is not
replayed.
