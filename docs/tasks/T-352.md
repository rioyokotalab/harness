## Decisions

- D-001: identify targets by an exact pane-local `@harness_target` role, pane
  index, repository cwd, supervisor target, and immutable pane ID inside one
  exact canonical window. The role remains authoritative if an application
  changes its presentation title; the monitor restores that title.
- D-002: auto-recovery treats a target as attached only when an attached
  client's selected pane is that exact target pane. It never infers target
  identity from the shared window alone.
- D-003: recovery remains bridge-first. A replacement is accepted in a
  provisional window before its pane is moved into the canonical window; the
  old exact leaf is retired only after acceptance.
- D-004: enforce pane order with process-preserving `swap-pane -d`; do not
  continuously enforce geometry or disturb zoom state.
- D-005: publish and test before live mutation. Pause only monitor/helper
  loops, preserve project panes, and retain an exact `break-pane` rollback.
- D-006: no additional owner interview is needed. “Do as you recommend” is the
  explicit go for this frozen plan.
