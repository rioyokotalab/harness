## Status

Phase: `complete` (owner closed 2026-08-01 14:02).

All five requested items are delivered and running on `aist`, `home`,

Final sweep: every Mac reports `codex=live claude=live claude_auth=ok
codex_remote_control=ready`. The legacy `harness-codex-resume` and `claude-rc`
sessions are retired everywhere. `att` now attaches this host's canonical
session. Published as PRs #517, #518, #519, #520, #521, #522, #523, #525,
#526, #528, and #529.

Ten defects were found by piloting rather than by tests, each fixed with a
regression test and several mutation-tested: tmux prefix-matching on
unanchored targets; a launchd PATH without Homebrew; `display-message`
reporting a phantom window as live; create-and-die thrash from an orphaned
supervisor; a guard that self-matched on any command line mentioning it; a
split tmux socket that made the session invisible; a blocking
remote-control start that stopped every later tick; pinning the wrong socket
directory in the first attempt at that fix; launching Claude without
credentials; and `--continue` on a host with no conversation to resume.

Known limitation, accepted by the owner: LaunchAgents run only in a GUI
session, so a Mac that reboots unattended stays offline until someone logs
in. The pre-login access route was considered and explicitly dropped.

Residual risk, not addressed: the last three defects share one shape, a
window recreated every tick although it cannot succeed. Each specific cause
is fixed; the class is not. A respawn backoff reporting
`claude-deferred-unstable` after N rapid failures would cover it. The
send-only injection skill is merged but has never been exercised end to end.

Operational note for any future Mac: log Claude in over SSH, not in the GUI.
An SSH login writes `~/.claude/.credentials.json`, which the launchd agent
can read; a GUI login stores the credential in the login Keychain, which
neither SSH nor launchd can read, and the window then defers as
unauthenticated.
