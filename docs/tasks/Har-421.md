# Har-421 — Bound Slack message results to whole-item prefixes

The first exact-resource Swallow read reached Slack once but the returned
message list exceeded the broker's 64-KiB wire envelope. Har-415 correctly
discarded it and returned only `provider-result-too-large`; no source value was
printed or persisted, and the consumed read was not retried.

When an otherwise valid channel/thread message result exceeds the envelope,
select the largest whole-message prefix whose fully escaped JSON-RPC response
fits the exact wire bound and force `has_more=true`. Never split an item or
estimate raw size before JSON escaping. If even one item cannot fit, return a
small value-free `provider-item-too-large` failure. Keep non-message oversize
results on the existing generic failure path.

Focused tests prove exact encoded-size enforcement, ordered whole-prefix
selection, truncation signaling, and suppression of an individually oversized
private value. The complete Slack suite and repository-selected integrated gate
pass. Har-421 is complete with the protected candidate; another live read
requires a separately authorized changed-input acceptance after deployment.
