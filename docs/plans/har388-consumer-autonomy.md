# Har-388 consumer autonomy and efficiency plan

## Frozen objective and authority

Improve the generic Harness communication and producer/consumer framework from
direct, content-blind interaction with the existing Personal Codex consumer.
The owner authorized Harness and repository-local Personal implementation,
ordinary protected Git publication, repeated bounded subtask exchanges, and
safe execution of eligible Personal ledger work. This does not authorize pane
capture, private payload transfer into Harness, connector or external writes,
credential access, bypassing owner choices, or autonomous message loops.

## Benchmark

Record per iteration: route submission/result; request/report schema validity;
eligible task and disposition; unplanned producer interventions; confirmation
count; cold-start files and bytes; elapsed time; command and validation count;
changed owning tests; and safety invariants. Baseline route success is zero
because no Local Personal target exists. Target is zero unplanned intervention
after the final iteration, one requested confirmation between subtasks, correct
ready/blocked state, and no unnecessary full-suite rerun.

## Independent streams and rollback

- Harness: isolated branch/worktree, focused tests before behavior, complete R3
  for communication or validation-router changes, protected PR, then rollout
  through canonical `main`. Roll back by reverting the protected change.
- Personal: private producer packet first, isolated consumer implementation,
  `./bin/validate`, writer-boundary checks, protected PR, terminal receipt, and
  producer reconciliation. Roll back only in Personal.
- A finding is handled LIFO in its owning repository. A gate in one stream does
  not acquire or mutate the other stream.

## Duration contract

Cutoff is 2026-08-04 09:00 Asia/Tokyo. Evidence cadence is one slice for each
requested hour, plus a checkpoint after every material result or failure.
Material work stops at 08:15; final integration is 08:15–08:50; cleanup and
durable handoff finish by 09:00. Stop early only if every eligible task is
complete, remaining tasks are truthfully gated, acceptance passes, and all ten
slices are evidence-backed. Otherwise continue reducing time and tokens per
task without expanding authority.
