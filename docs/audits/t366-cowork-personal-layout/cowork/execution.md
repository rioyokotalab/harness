# Driver execution

## Steps and results

1. The first Claude synthetic topology experiment inherited the live tmux
   socket and destroyed the prior server. All claimed live pane/process
   preservation was invalidated, the incident was checkpointed, and execution
   stopped before any attempted repair.
2. The owner authorized direct reconstruction into the final topology. Codex
   rebuilt the mutable baseline from process and tmux metadata only; no pane or
   transcript content was read.
3. A changed-input Claude reciprocal pass used repository reads only, accepted
   the revised exact-session benchmark, and was imported with a valid receipt.
4. Target profiles now declare exact window and pane locations. Harness and
   Personal may intentionally share the Harness repository while launchers,
   monitors, recovery, and message routing select explicit role and exact
   session identity.
5. The isolated tmux regression now removes inherited `TMUX` and uses one
   explicit private socket. It constructs and validates `harness` windows
   `cowork`, `codex`, and `claude`, each with two even-horizontal panes.
6. Focused target, runtime isolation, thread recovery, Codex monitor, Claude
   monitor, recovery-helper, messaging, alias, skill-routing, safety, Personal,
   and final-layout suites pass. Full phase-1 validation remains next.

## Deviations

- Process-preserving migration is impossible because the first synthetic test
  killed the old tmux server. The owner explicitly selected fresh direct
  reconstruction instead of restoring the obsolete `projects` topology.
- Personal now has distinct Codex and Claude saved identities in the managed
  topology, superseding T-355's earlier no-persistent-TUI default for this
  owner-requested layout.
