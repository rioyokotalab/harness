measured the matched duration startup at 84,100 words and the clean complete
suite at 114.77 seconds.  Both accept move-only indexed board compaction as the
dominant context win.

strict required checks, squash/rebase-only methods, and exact bypass actors.

The live value is authoritative; correcting only tracked files requires no
hosting write.

and squash-merge-tree equality.  This supports tree-bound local evidence and
removal of duplicate private `main` runs.  Official GitHub documentation
supports job-level owner skips as successful required statuses, bills private
hosted jobs by rounded time, and warns against persistent self-hosting for
untrusted pull requests.

The independent runtime audit also established that the normal focused
manifest omits `test-codex-targets.sh`, long-lived project supervisors retain
mutable Harness script inodes, legacy Harness CWDs remain accepted for Students
and Swallow, and ambient `HARNESS_ROOT` can misdirect project commands.  These
are retained implementation findings; no live process is interrupted by this
task.

## Disagreements and uncertainty

Claude initially interpreted the stale approval fixture as contradicting the
plan.  Exact live readback resolved the discrepancy: all live counts are zero,
while the repository fixture/test are wrong.  Harness and Swallow retain
owner/admin always-bypass actors; Students retains an owner pull-request
bypass.  The existing Harness merge-control document incorrectly says there is
no bypass actor and must be corrected with the fixture.

Local receipts are not independent validation.  The accepted private design
trades merge-time hosted prevention for same-trust-root auditable
self-attestation and a weekly independent hosted opportunity. GitHub's
best-effort scheduler does not provide a hard seven-day completion bound.
Direct bypass pushes also lose immediate private `main` hosted validation.
This is an explicit owner-priority tradeoff, not an unchanged-safety claim.
Non-owner CI and Students boundary enforcement are unchanged.

Account billing/organization policy remains unknown without `admin:org`.
No authentication expansion, ruleset write, runner registration, or billing
write is needed.  Current live supervisors will continue holding mutable
checkout bytes until a later safe natural restart or separately coordinated
rollout; implementation must not interrupt active project work.
